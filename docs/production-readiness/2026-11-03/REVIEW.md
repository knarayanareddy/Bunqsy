# Bunqsy review

## Scope and verdict

Revision `472eeda591d8975775085f98637149096a6cacc7` is a financial-guardian implementation/prototype, not a certified banking system. This is a partial static review; runtime, tests, financial transactions and deployments were **not run**. Several action and webhook controls require correction before a production decision. Exploitability, actual provider behavior and financial correctness remain unverified.

## Architecture and product boundary

The [README:13–22](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/README.md#L13-L22) claims monitoring, interventions, card actions, voice and bookkeeping. The tree separates a daemon, React frontend, shared types, presentation app and `mock-unzip` simulator. The daemon integrates bunq, a model provider, voice services and SQLite; its [entry:14–21](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L14-L21) imports several route modules. A presentation or simulator is not proof of a live banking path. Other route internals and inherited hooks remain largely uninspected.

## Findings ledger

- **BQ-01 — High, confirmed static:** [entry:100–115](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L100-L115) uses `prodOrigins.length > 0 ? prodOrigins : true`; separately, [entry:163–165](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L163-L165) listens on `host: '0.0.0.0'`. Missing production origins permit all origins while the service binds all interfaces. Perimeter and exploitability are unverified; fail closed and independently enforce authentication, not CORS alone.
- **BQ-02 — High, confirmed static:** [entry:44–68](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L44-L68) reads `sessionToken: row.session_token` and inserts `(installation_token, session_token, user_id, public_key_pem, private_key_pem,`. Encryption and access controls for disk, DB, backups and processes were not inspected. Determine custody before connecting real accounts.
- **BQ-03 — Medium, confirmed static:** [entry:138–144](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L138-L144) assigns `webhookRegistered = true` before `registerNotificationFilter(...)`, whose rejection is only logged. - **BQ-04 — Medium, confirmed static:** [entry:157–161](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L157-L161) selects `counterparty_iban FROM transactions` and returns `row?.counterparty_iban ?? [Bootstrap:97–151](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/index.ts#L97-L151) registers the routes without an explicit global auth hook in that range. Inherited hooks, other modules and deployment controls remain unverified; neither universal lack of authentication nor a successful bank action is established. - **BQ-08 — High, confirmed static; execution risk:** [execute:55–88](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/bunq/execute.ts#L55-L88) separately reads status before an unconditional confirmation update and requires `row.status !== 'CONFIRMED'` to reject execution; it shows no atomic execution claim. [execute:123–169](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/bunq/execute.ts#L123-L169) calls `fetch`, logs each step result, throws on failure and marks the plan `EXECUTED` only after the loop; no idempotency key is visible in that fetch. [execute:245–273](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/bunq/execute.ts#L245-L273) maps payment and savings steps to payment requests. Concurrent calls, partial success and a lost response risk repeated or ambiguous effects; no duplicate payment has been demonstrated. Claim atomically, record durable outcomes and reconcile before retry; provider idempotency support is unverified.
- **BQ-09 — High, confirmed static; webhook trust risk:** [webhook handler:480–514](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/routes/api.ts#L480-L514) takes the first `x-forwarded-for` value, checks signatures only `if (sessionRow?.server_public_key)`, and logs `Signature check error (non-fatal)` before continuing on exceptions. It supplies `JSON.stringify(req.body ?? {})`, while [validator:37–50](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/bunq/webhook.ts#L37-L50) describes verification against the `raw body`. [Origin helper:23–32](https://github.com/knarayanareddy/Bunqsy/blob/472eeda591d8975775085f98637149096a6cacc7/packages/daemon/src/bunq/webhook.ts#L23-L32) allows all IPs in sandbox. Missing keys and exceptions therefore fail open in the sampled handler; proxy stripping, provider byte rules, runtime occurrence and exploitation remain unverified. Fail closed in production, verify proxy trust and use provider-defined signed bytes with replay protection.

## Five-discipline assessment

**Correctness:** BQ-03, BQ-04 and BQ-08 are static observations, not measured outcomes. Existing per-step result logging is not proof that ambiguous or partial effects are safely reconciled.

**Automation/testing:** The tree lists `packages/daemon/src/bunq/signing.test.ts`; sampled root and daemon manifests expose build/dev but no test script. Other tests may exist. Historical Pages success is not an end-to-end financial gate.

**Operations:** SQLite files including WAL/SHM appear in the inventory; their contents were not examined. Verify backup, restore, key rotation, incident response and webhook retry with synthetic data. Owner-approved sandbox use is future work, not a result of this review.

**OWASP/security:** BQ-01, BQ-02 and BQ-07–09 expose boundary and custody concerns. Inspect every API and WebSocket route, inherited authentication, prompt injection from external data, secret exposure, dependency integrity, logging, retention and account isolation. No complete threat assessment was performed.

**UI/UX/accessibility:** The prior draft reports sampled frontend imports for voice, transaction, approval and bookkeeping screens. Distinguish simulator from live execution; display exact account and amount before authorization. Keyboard, screen-reader, confirmation and error behavior remain untested.

## Blockers and owner questions

Who owns keys, callback domain, deployment perimeter, backups and incident response? Which account, actions and sandbox are authorized, and what provider idempotency and reconciliation guarantees apply? Regulatory, privacy and banking review and separate owner approval precede any real-money deployment. No certification is asserted.
